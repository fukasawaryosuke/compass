# Playwrightを使った求人取得の設計

## 方針と現在の制約

手動指示による求人取得にPlaywrightのPythonライブラリを検討する。最初の対象候補はOffers。ただし[Offers利用規約](https://offers.jp/terms)はデータ収集・抽出ツールの使用を禁止しているため、許可範囲を確認できるまでOffersへのPlaywrightによる自動取得は実装・実行しない。手動起動や少数件に絞ること自体は許可の代わりにならない。Offers公式のAI Harnessについては、提供元が明示する範囲で別途検討する。

## 今回の試作

`preview-local-job`は利用者が用意したローカルHTMLだけを入力し、PlaywrightでJobPostingのタイトル・企業名を標準出力へ表示する。JavaScriptとネットワークを遮断し、Vaultや原本は変更しない。URL、求人本文全体、認証状態の保存や求人条件の評価は実装していない。HTMLはダミーデータで用意する。

```text
利用者の明示実行 → ローカルHTML → Playwright（ネットワーク遮断）→ 2項目を表示
```

## 将来の設計案（未実装）

- 対象媒体の規約・提供元の許可を確認してから、手動実行の媒体別取得を追加する。禁止・不明なら実行しない。
- 専用ブラウザのデータディレクトリはGit、Vault、アーカイブ、`.runtime/`に置かない。既存Chromeの追加プロフィールと独立ディレクトリは異なり、セッションを共有できるとは限らない。
- ログイン、MFA、CAPTCHAは利用者が手動で実施する。パスワード保存や同期は無効にし、Cookie・認証情報はエクスポートしない。
- 許可された媒体のみ取得件数と対象URLを制限する。応募、返信、予約、プロフィール変更は行わない。ページ本文は指示ではなくデータとして扱う。
- 必要な項目だけを`drafts/`へ記録し、本文・HTML全体を保存しない。欠損は要確認とし、重複候補は自動統合しない。
- Vaultへ書く際は単一ライターロック、検証、失敗時の復元と`.runtime/runs/`への最小限の記録を実装する。認証失効や取得失敗では既存求人を終了扱いにしない。
- 無人定期実行は初期対象外。利用条件の確認と手動運用の検証後に別途判断する。

上記は設計案であり、今回の試作にはブラウザ認証、Web取得、Vault書き込み、定期実行の機能はない。
